Got Questions?

Frequently Asked Questions

Everything you need to know about implementing and operating Auth Branding in Odoo 19.

Will editing a draft change the live login page for visitors?
No. Auth Branding maintains strict production isolation. Public authentication routes only render the active published version. Changes made in the editor remain in draft status until you explicitly choose to Publish or activate a schedule.
Can every company in a multi-company setup have unique branding?
Yes. Auth Branding is fully multi-company aware. Configurations, custom presets, scheduled jobs, and published version histories are tied to the active company and protected by Odoo's native record rules.
What happens if I edit a draft after scheduling a future release?
The scheduled release remains unchanged. When you create a schedule, Auth Branding captures an immutable snapshot of all settings and binary assets (logo, favicon, background image). Any subsequent modifications to your working draft will not alter the scheduled launch.
Does Auth Branding work with OAuth and social login providers?
Yes. Auth Branding styles provider buttons supplied by Odoo's standard authentication and OAuth modules (Google, Microsoft, Apple, GitHub, Keycloak, etc.). You can configure button shapes (rounded, pill, square, icon-only) and visibility without interfering with provider authentication credentials.
Can I migrate brand designs between staging and production databases?
Yes. Auth Branding provides a built-in Export & Import utility. You can export a versioned JSON package with embedded base64 image assets, import it into another database as a draft, verify it in preview, and publish when ready.
Is custom CSS supported for edge-case branding requirements?
Yes, with safety sanitization. An Advanced tab allows experienced administrators to provide custom CSS declarations. For security, external network imports, scripts, JavaScript execution, and unsafe data protocols are rejected automatically.
